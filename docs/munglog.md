# 멍로그: 집에 남은 휴대폰으로 반려견의 짖음 확인

외출 중 반려견이 짖는지 확인하려고 만들었습니다. 집에 둔 Android 폰이 소리를 감지·보관하고, 밖의 폰과 웹에서 알림과 기록을 확인합니다. 모든 소리를 계속 서버에 올리는 대신, 기록 정보부터 보내고 사용자가 요청한 녹음만 전달합니다.

제품의 문제와 우선순위는 직접 사용하며 정했습니다. Android·Rust 음향 처리·API·DB·웹을 다뤘고, 고도화 구현과 회귀 검증에는 AI 코딩 도구를 활용했습니다. Kotlin/Compose, Rust/JNI, TFLite, SQLite/WorkManager, Axum/SQLx·PostgreSQL, R2를 사용하며 GCP·Docker·Cloudflare 환경에서 운영과 개발 환경을 구분했습니다.

**기존 앱은 출시했습니다. 아래 개인화 학습은 2026년 10월 15일 개발 환경에서 확인한 내용이며, 운영 출시 기능과 구분합니다.**

## 1. 큰 소리를 찾는 것과 짖음을 확인하는 것은 달랐다

문·의자·비닐 소리도 순간적으로 큽니다. 모든 입력에 무거운 모델을 적용하거나 감지 후보를 바로 짖음 횟수로 세면 계산과 오탐을 함께 늘릴 수 있었습니다.

16kHz 오디오에서 Rust가 FFT 기반 대역 정보와 음량·주변 소음을 계산해 후보를 좁히고, Android의 YAMNet TFLite가 최종 분류하도록 나눴습니다. 주변 소음 보정 범위와 같은 자극을 반복 감지하지 않을 조건도 제한했습니다.

실기기 로그에서 후보가 생긴 뒤 모델이 보류한 구간을 확인했습니다. 이후 후보 생성·최종 판정·저장·알림을 따로 추적했습니다. 후보 수는 실제 짖음 수가 아니며, 거리와 음량이 다른 환경의 정확도는 정답 음원을 갖춘 별도 평가가 필요합니다.

## 2. 오탐을 줄이려다 진짜 짖음까지 놓쳤다

직접 사용하며 기침과 의자 소리의 오탐을 발견했습니다. 부정 평가에 따라 전체 판정 기준을 올리는 방식은 실제 짖음도 보류하는 문제를 재현했습니다. 사용자의 뜻은 ‘모든 소리에 엄격해져라’보다 ‘이 소리는 우리 집 의자다’에 가까웠습니다.

이미 평가한 녹음을 다시 활용해 폰 안에서 작은 개인 모델을 학습하는 방향으로 바꿨습니다. YAMNet 전체를 재학습하는 대신 고정된 521개 출력 점수 위에 이진 분류와 사용자 이름 분류 모델을 학습했습니다. AAC 원본은 메모리에서 디코딩하며 개인 음원과 모델을 중앙 학습용으로 모으지 않았습니다.

같은 원본에서 자른 구간이 학습·검증 양쪽에 들어가지 않게 묶고 중복을 제거했습니다. 공개 시험 음원으로 재학습·재로딩을 확인했고, 반복 인코딩한 무음은 독립 원본 하나로 처리되어 적용이 막혔습니다. 후보 검증·명시적 적용·이전 모델 복원도 구분했습니다. 집별 오탐 감소율은 아직 측정하지 않았고, 이 모델은 앞단에서 놓친 소리를 복구하지 못합니다.

## 3. 밖에서 누른 평가가 집의 학습으로 이어져야 했다

평가는 보는 폰에서 하지만 원본과 학습 모델은 수집폰에 있습니다. 서버에 저장됐다는 표시만으로 전달 완료라고 할 수 없었습니다. 내려받은 평가를 처리하지 못했는데 조회 위치만 전진하면 다음 동기화에서도 영영 건너뛸 수 있었습니다.

조회 위치와 처리 결과를 같은 DB 트랜잭션에 저장했습니다. 수집폰의 직접 평가와 원격 평가는 출처를 구분하고, 현재 계정·가정·수집기의 소유 범위를 다시 확인했습니다. 기록 전송은 SQLite 대기열과 WorkManager로 재시도하고 서버의 멱등성 키로 중복을 막았습니다. 알림은 DB에 보낼 일을 남기는 outbox를 거쳐 전달합니다.

DEV에서 실제 분류 메타데이터·선택 알림·원격 모델 초기화의 확인 응답을 관찰했습니다. 요청 녹음은 현재 권한을 다시 검사해 짧게 유효한 비공개 R2 사본으로 전달합니다. 무음 시험의 재생·삭제 거부는 확인했지만, 새 개인 모델이 만든 동일 녹음의 알림부터 재생·삭제까지 전체 경로는 남아 있습니다.

## 4. 역할을 바꾸거나 서버가 멈추면 사용자는 길을 잃었다

앱을 설명하려고 보는 폰을 수집기로 바꿨다가 이전 연결 설정을 잃었습니다. 감지는 됐는데 서버가 응답하지 않을 때는 보는 화면이 단순히 ‘기록 없음’처럼 보여, 조용한 것인지 장애인지 알기 어려웠습니다.

역할 변경을 로그아웃과 분리하고 최근 가정 선택과 설정을 최소한으로 보존했습니다. 복원할 때 현재 멤버십과 OS 권한을 확인해 철회된 연결을 되살리지 않도록 했습니다. QR·기기 정보·기록 상세는 실제 행동 순서대로 찾게 정리했습니다. 조회 성공 0건, 네트워크·인증·서비스 실패, 오래된 기록은 서로 다른 상태로 표시했습니다.

통제된 수집폰 복구 상태가 서버를 거쳐 보는 폰에 표시되는 것을 확인했고 재시도에는 한도를 뒀습니다. 가족 강퇴 후 옛 초대로 재가입하는 결함도 현재 권한을 재검사해 차단했습니다. 다만 최근 상태 보고는 마이크가 지금 물리적으로 듣고 있다는 보증이 아니며, 장시간 OS·마이크 장애 복구는 추가 시험이 필요합니다.

## 5. 늦게 끝난 작업이 새 세션을 바꾸지 않게 했다

감지 중지·역할 변경·삭제 뒤에도 인코딩이나 업로드가 늦게 끝날 수 있습니다. 이전 작업이 새 기록을 만들거나 삭제한 파일을 다시 올리는 문제를 막기 위해 저장·반영 시점에 세션과 소유 범위를 다시 검사했습니다. 무효화된 파일은 정리하고 DB 기록과 집계는 함께 저장했습니다.

개인 분류의 정상 파일이 계속 업로드되지 않는 문제에서는 Android 파일 경로의 별칭과 정규화된 경로를 다르게 비교한 원인을 찾았습니다. 검사를 끄지 않고 신뢰할 상위 경로부터 정규화한 뒤 하위 파일을 검증해, 정상 업로드와 다른 파일 거부를 함께 확인했습니다.

반복 호출도 조사해 매 오디오 프레임의 불필요한 시스템 조회를 줄였습니다. 합성 입력의 조회 횟수 감소는 확인했지만 배터리·온도 개선율로 바꾸어 쓰지 않았습니다. 새 개인화의 운영 전환, 동일 녹음의 전체 전달, 가정별 오탐·미탐과 장시간 발열 측정이 다음 과제입니다.
